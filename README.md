# KTX 당일배송 — 3구간 릴레이 특송 프로토타입

MOVE-AI CHALLENGE 2026 · 한국철도공사 트랙 제안작.
**공식 서비스가 아니며, 운임 일부와 표시 수치 일부는 가정치입니다.**

역에 가지 않고 오늘 안에 보내는 3구간 릴레이 배송.
**집앞 →(시민 운반)→ 출발역 →(KTX 특송)→ 도착역 →(시민 운반)→ 집앞.**

파는 것은 속도가 아니라 **확률**이다 — 화면의 세 구간 확률을 곱하면 종합 확률이
그대로 나온다. 지어낸 숫자가 아니라 몬테카를로 10,000회의 계산 결과다.

## 실행 방법

### 백엔드 (FastAPI · Python 3.11)

```bash
cd backend
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt   # (macOS/Linux: .venv/bin/pip)
cp .env.example .env                             # 키를 채운다 (아래 참고)
.venv/Scripts/python -m uvicorn app.main:app --port 8020 --reload
```

`.env` 항목:

| 키 | 용도 |
|---|---|
| `DATA_GO_KR_KEY` | 공공데이터포털 인증키 (TAGO 열차정보) — **없으면 시간표를 못 받아 경로가 생성되지 않는다** |
| `GEMINI_API_KEY` | 자연어 접수 (없어도 규칙 폴백으로 같은 흐름이 돈다) |
| `DEMO_MODE` | `true` 면 마스터 인계 코드 `000000` 허용 (시연용) |
| `DEMO_TIME` | `12:00` 처럼 넣으면 서비스 기준 시각 고정 (시연용 — 촬영 후 비울 것) |
| `SEED_ON_START` | `true` 면 기동 시 DB 가 비어 있을 때 지난 7일 운영 이력(~230건)을 생성 |

### 프론트엔드 (Vite + React)

```bash
cd frontend
npm install
npm run dev        # /api 는 127.0.0.1:8020 으로 프록시
```

### 테스트 (서버·키 불필요)

```bash
cd backend
.venv/Scripts/python tests/check_all.py    # 성질 검사 18항목
```

### 배포

- 백엔드: Railway + Docker (`backend/Dockerfile` · `railway.json`)
- 프론트: Vercel (`frontend/vercel.json`, 빌드 환경변수 `VITE_API_BASE`=백엔드 주소)
- 푸시 전 로컬 확인: `docker build -t timeproof-api backend && docker run --rm -p 8020:8020 --env-file backend/.env timeproof-api`

## 데이터 출처 3종과 각각의 한계

| 출처 | 쓰는 곳 | 한계 |
|---|---|---|
| **국토교통부 TAGO 열차정보** (data.go.kr `1613000/TrainInfo`) | 오늘 운행 편성·시각·운임 — 시간표를 하드코딩하지 않고 당일 수신 | 운행 '계획'이다. 포털이 날짜를 하루 밀어 주는 특성이 있어 응답 날짜를 검증하며 재요청한다 |
| **사업자 공표 정시운행률** (한국철도공사 2024 · SR 2025 상반기, 5분 기준) | 열차가 늦을 **확률** (KTX 82.69% · SRT 96.48%) | 연간·반기 평균이다. UIC 15분 기준을 쓰면 전부 99%에 붙어 정보가 없어지므로 보수 기준을 채택 |
| **한국철도공사 열차운행정보** (`B551457/run/v2`) | 늦는 **크기**(지연 분포)의 실측 교체 대상 | **자료가 어제까지다 — 실시간이 아니다.** "지금 몇 분 늦었나"는 알 수 없어 진행 화면의 지연은 수동 입력(시연)이며, 현재 크기는 가정값(지수분포 평균 12분)을 쓴다 |

**하는 척하지 않은 것** — 본인확인(PASS)·안심번호 발급은 계약이 필요한 영역이라
형식만 남기고 화면에 '모의'라고 밝혔다. 실시간 열차 지연도 위 한계 때문에 수동
주입이며 화면에 "실제 운영에서는 관제 연동"이라고 적었다.

## 가정인 것 (전체 목록은 운영자 화면 · `GET /api/provenance`)

- 채널 추가 운임(+1,000~+7,000)과 배분 — 통상 생활물류 요율 참고 **제안값**
- 구간 소요 분포 (median +35%·(1−R) · σ 0.18+0.15·(1−R)) — 통행속도 통계 기반 유도
- 지연 크기 지수분포 평균 12분 — 운행정보 실측으로 교체 대상
- 시민 운반 매칭 리스크 0.05 · 무인함 회수 리스크 0.03 — 파일럿 실측 대상
- 이동수단 속도 (도보 4.5 · 러닝 9 · 자전거 15 · 대중교통 18 km/h)
- 운반자 명단·운영 이력 — 시연용 가상 데이터 (결과는 예측 확률에서 생성)

실측인 것 — 특송 공시 요율(규격 6등급·무게/거리/가액 할증), 취급역 14곳,
접수 마감(출발 30분 전), 편성별 화물 제한, 약관 조문(제10조·제20조), 정시운행률.

## 시연 세팅

```
.env: DEMO_MODE=true · DEMO_TIME=12:00 (12시 — 남은 편성과 빠듯한 여유가 공존)
```

- **신뢰도 대조**: 강남→서면, 데드라인 **17:00** 에서 최대로 벌어진다 —
  조민재·현민채 88.2% vs 김성민·김나은 51.2% (**37.0%p**). 17:30 도 30.8%p.
- **지연 장면**: 같은 구간 데드라인 **17:50** (여유 17분) — 탑재 94.3% →
  12분 지연 77.5%(흡수) → 25분 지연 0%(붕괴) → 역 수령 전환 94.6%(회복).
- 인계는 `DEMO_MODE` 마스터 코드 `000000`.
- **촬영이 끝나면 `DEMO_TIME` 을 반드시 비운다** — 화면에 고정 시각 표시가 없다.
